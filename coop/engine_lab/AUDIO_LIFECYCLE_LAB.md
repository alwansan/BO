# Read-only audio observation in the original PC lab

The existing `black-coop-original-engine-lab.yml` now observes audio creation and destruction during its bounded 1200-second original PC two-player run. It retains the exact PC/runtime/DSP pins and private owner-image validation. It preserves the existing movement, firing and P1 restoration acceptance checks.

After generation, `audio_lab.py` requires exactly one definition each of original `7EF50` and `7EDB0` before writing any generated source. The wrapper calls the unmodified original body exactly once. The observer reads the calling thread's own guest stack to identify supplied embedded storage, increments interlocked counters, and maintains a private bounded ring of storage addresses. The ring uses an observer-only try-lock. A busy observer drops its observation and increments `observation_busy` while the original call continues.

No original object bytes are sampled or copied. No guest memory, guest registers, audio callback, constructor argument or destruction decision is changed. On return from the existing PC `black_p2_banks_take`, the game thread counts retained creation storage addresses within the current original FPV range. This shows storage-address reuse after the original restoration boundary. It does not establish that an object was successfully published, remains live, or can safely be moved. Ring evictions and missed observations limit coverage.

The aggregate contains only bounded integer counters. `other_thread_calls` compares a callback thread to the first observed audio-call thread. `overlap_calls` counts overlapping observed create/destroy calls. Neither counter alone proves absence of other audio readers. `retained_fpv_storage` is a count of retained storage addresses, and it does not assert publication ownership. `audio_observer_executed` requires constructor calls and a post-take observation. A missing audio file remains an explicit null observation. Audio observations do not change or replace the existing original gameplay acceptance result.

Only `summary.json` leaves the private runner. Addresses, guest stack data, owner assets, generated instruction bodies, private paths and raw logs remain private and are removed with the disposable engine checkout. Calibration tests exercise transformation drift, privacy rejection, thread/overlap counts, ring removal and missing memory. They execute synthetic memory only. A new workflow run is required to establish actual engine observations.
