# Work58 — حماية جيل نشر الجزء والتحقق من إصلاح اللوحة

- تأكد نجاح [Android 10](https://github.com/alwansan/BO/actions/runs/46102965675) على `9f6fe52`: خرج الاختبار بـ `AUTOMATIC_ROOM_DOWNLOADS_LOG_PASS` و`GUEST_ROOM_REOPEN_PASS`. فُتحت لوحة الضيف، أُغلقت مرة لوصول Start، ثم بقيت مفتوحة بعد إعادة فتحها بالتذكرة نفسها مع بقاء الاتصال. نجح كذلك [المصدر](https://github.com/alwansan/BO/actions/runs/46102965753) و[TLS](https://github.com/alwansan/BO/actions/runs/46102965703).
- أضيف نطاق تسلسل اختياري لنشر الوحدة: يتطلب جيلًا حيًا، ويرفض الدخول دون انتظار إذا كان النشر جارياً، ويعيد فحص الجيل بعد العملية. إعادة نشر من الخيط نفسه أثناء العملية تبطل نتيجتها. الاستثناء يحرر النطاق تلقائيًا. الاختبار الاصطناعي تحقق من هذه الحالات بـ ASan/UBSan.
- نجحت اختبارات C++ الثلاثة للحارس وطابور الأحداث وحارس Start، و22 اختبار تجهيز مصدر، وتجميع وحدات Android السبع محليًا بعد التغيير.
- الحارس غير مفعل في المنتج؛ المنشئ الافتراضي يبقي سلوك الرصد السابق، ويرفض عمليات النطاق الاختيارية. القفل يحمي حدود النشر المرصودة فقط، ولا يدّعي ملكية كل ذاكرة المحرك أو حل مخاطر انتظار خيوطه. يلزم اختبار محرك قبل تفعيل أي كاتب للضيف.
- تبقى نتيجة تجربة المالك سلبية للعالم المشترك. نجاح لوحة الغرفة والسجل أو حارس C++ ليس إثباتًا لظهور البشر أو تطبيق الأفعال لدى الضيف. التالي: اختبار الجزء مع النطاق وقراءة نتيجة التصادم، ثم موارد صوت P2 والممثل المرئي والتقدم المشترك.
