# اختبار Probe3 بعد نجاح بناء APK فقط

الحالة الحالية: تعليمات جاهزة، وليست طلب اختبار قبل تأكيد artifact. النسخة تشخيصية للقراءة فقط، ولا يوجد co-op أو لاعب ثانٍ بعد. لا تعِد اختبار baseline أو Probe2.

1. ثبّت APK الذي يحمل الحزمة `org.bocoop.black.probe3` والاسم **BLACK Probe 3 - READ ONLY**. اترك التطبيقات السابقة وملفات الحفظ كما هي. استورد نفس `game.iso` الذي قبله Probe2 إن طلب التطبيق الملف؛ لا تعدّل ISO.
2. اختر **Start capture** عند عرض نافذة التشخيص. ادخل مهمة القصة. الالتقاط محدود إلى180 ثانية داخل العالم؛ ابدأ خطوات الاختبار بمجرد الدخول وتجنب انتظار مشاهد طويلة.
3. اقترب من أعداء ظاهرين، وألحق الضرر بأحدهم ثم اقتله. تحرك قليلاً حتى تتغير الشخصيات المرئية. يكفي هاتف واحد لهذه المرحلة.
4. أعد آخر checkpoint أو أعد المهمة مرة واحدة أثناء الالتقاط. ادخل العالم وتحرك بضع ثوانٍ. هذا يفحص إعادة استخدام الخانات وإعادة ضبط الرقم التسلسلي، ولا يثبت multiplayer.
5. بعد نحو3 دقائق من بدء اللعب، ضع التطبيق في الخلفية ليأخذ exporter لقطة حديثة، ثم افتح أحدث مجلد بتاريخ التجربة داخل Downloads/Games/cl/black log/logs/BLACK-Probe-[date]/.
6. أرسل **coop_probe.txt** الأحدث فقط، مع ذكر ما إذا حدث تعطل وما إذا قتلت عدواً وأعدت checkpoint/المهمة. لا حاجة لإعادة رفع ISO أو Android/data أو كل سجلات التطبيق. الملف الخام يبقى ضمن مصدر المالك؛ لا يُنسخ إلى BO العام.

## تفسير النتائج للمطوّر
- بداية السجل قد تبقى HOOK001 من البنية المشتركة؛ تمييز Probe3 يكون بالحزمة/source/report وبأحداث `event=pool`، لا بالاسم وحده.
- pool.valid=false يعني قراءة غير متاحة أو لقطة غير متسقة؛ لا يُفسر موتاً أو غياب شخصية. التقط معدل الرفض قبل اقتراح تعديل.
- tuple داخلactors: `[slot,container,serial,state,resource320,resource35c]`. slot خانة فيpool وليستplayer/networkID. container0free وتصفّر بقية metadata عمداً لأنها قديمة؛1/2/3قوائم مراحل،لا تعِد تسميةstate1/2 موتاً مؤكداً دون ربط بما حدث في الاختبار.
- world_epoch تغير مؤشر العالم فقط. reset_sequence عدد successfulAL1 returns للرصد أثناءopt-in. اقرأ الاثنين معserial/slot،ولا تزعم هوية دائمة أو كشف كلtransition/ABA.
- الموردان320/35c قيم pointers مرصودة؛لا يثبت اشتراكهما ownership/render-instance. لا تُستدعَ دوالallocation/spawn/free من السجل أو منnetworkthread.
- التحليل القديم المصمم لـProbe2 قد لا يقبلpool records؛لا تستخدم نجاحه أو فشله لإثبات صلاحيةProbe3. تحقّق JSON والقيم والسياق أولاً،ثم أضف محللاً مستقلاً إذا لزم من السجل الفعلي.
